ICStudio workbench snapshot contract v1
=======================================

Authority
---------

The Java project model owns project state. The Swing workbench MUST NOT read or parse project
files. It receives an immutable ProjectSnapshot in-process from the transactional project
service, and its JSON form is exactly `ProjectSnapshot.summaryJson()`.

JSON fields
-----------

schemaVersion : integer, currently 1
projectId     : 32 lowercase hexadecimal characters (128-bit persistent identity)
name          : non-empty project name
revision      : non-negative safe integer
libraries     : non-negative safe integer
cells         : non-negative safe integer
views         : non-negative safe integer

No additional fields are accepted by the M1 workbench. The snapshot is immutable.

Security boundary
-----------------

- The workbench holds presentation state only: selection, scroll position, and layout.
- It has no filesystem, subprocess, project mutation, or MCP privilege.
- It binds a snapshot read-only; it cannot change the authoritative project.
- Native rendering is confined to the Skia scene surface; Swing owns windowing and focus.

Equivalence gate
----------------

For the same project revision, all of these payloads MUST agree:

1. `icstudio project show --path ...` (CLI)
2. The Swing inspector's displayed name, project ID, revision, and hierarchy counts
3. MCP `project.inspect` structured content

`SurfaceEquivalenceTest` enforces this gate in `java/icstudio-conformance`.
